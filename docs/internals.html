How SCAS stays exact, bounded, and inspectable.

A guide to the scanner-to-renderer pipeline, numeric and symbolic representations, error model, deterministic limits, and repository structure.

Execution pipeline

  1. The Unicode-aware scanner creates tokens with source spans.
  2. The recursive-descent parser creates an AST for statements and expressions.
  3. The interpreter executes in linked lexical environments.
  4. Exact numbers remain integers or reduced rationals; requested approximation enters the decimal/complex layer.
  5. Symbolic operations build immutable reference-counted expression trees and apply conservative rewrites.
  6. The documenter walks the same AST and interpreter state to emit semantic LaTeX fragments.

Number model

  • Integer: arbitrary-size BigInt.
  • Rational: normalized BigRational.
  • Decimal: arbitrary-precision BigDecimal under an active context.
  • Complex: arbitrary-precision decimal real and imaginary components.
  • Constants: exact symbolic pi, e, tau, and phi.

Verification

cargo fmt --all -- --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets --all-features

Tests cover unit behavior, CLI status/diagnostics, file fixtures, exact arithmetic properties, randomized symbolic invariants, the document renderer, graph sampling, and GUI state helpers. The seeded SymPy differential check runs in CI; see correctness and performance for its 100/100 result, workload timings, and limitations.

Known boundaries

The CAS intentionally advertises bounded algorithms. General Gröbner bases, unrestricted integration, arbitrary-dimensional eigensolvers/Jordan chains, general matrix exponentials, unrestricted hypergeometric sums and ODEs, and branch-complete limit analysis remain future work. See TODO_STILL.md for the living roadmap.

Mathematical boundaries are repeated beside each operation in the builtin reference.
