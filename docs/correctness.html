Correctness you can rerun.

Seeded differential checks, exact tests, fuzzing, release provenance, and fixed workload timings.

SymPy differential checks

scripts/compare_sympy.py generates integer polynomials with seed 20261011, runs SCAS, and compares symbolic results with SymPy 1.14.0. The recorded run passed 100 of 100 cases: 25 each for expansion, differentiation, polynomial GCD, and resultants. A mismatch exits nonzero and prints the counterexample.

cargo build --release --bin scas
python3 scripts/compare_sympy.py

The sample covers small univariate integer polynomials. It does not establish correctness for every domain, large input, or numeric function. The script accepts --seed and --per-family for additional runs.

Fixed SymPy comparison

Captured on 2026-10-11 using an Intel Core i5-8265U, Linux x86-64, Rust 1.79.0, Python 3.14.7, and SymPy 1.14.0. Times are median milliseconds per evaluation over five batches.

WorkloadSCASSymPy

SCAS batches include parsing and printed output with process startup amortized. SymPy calls its API on prebuilt expressions in a running Python process. These are task timings across different layers, so use them as reproducible observations rather than a general speed ranking.

python3 scripts/benchmark_sympy.py

Other evidence

  • cargo test --all-targets --all-features checks fixtures, exact arithmetic properties, reference vectors, resource limits, and document output.
  • Scanner and parser fuzz targets run in scheduled CI.
  • Special-function tests compare against independent high-precision mpmath vectors.
  • Release CI builds supported platforms, emits checksums, and creates build provenance attestations.
