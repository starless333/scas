Mathematical function reference

The official reference for every mathematical builtin currently registered by SCAS 0.1.0. Signatures use x for a value, expr for a symbolic expression, v for a vector, and A for a matrix.

Evaluation model

Integers and rationals remain exact. Decimals are arbitrary precision. Elementary functions support arbitrary-precision real and principal-branch complex evaluation. Exact expressions remain symbolic when SCAS cannot produce a safe exact result; use evalf(expr) or a decimal input to request approximation.

print(sin(pi / 6));       // 1/2
print(sqrt(2));           // sqrt(2)
print(evalf(sqrt(2)));    // decimal at the active precision
print([1, 2; 3, 4] * [5, 6]); // [17, 39]

The default precision is 100 significant digits. Batch mode accepts --precision N; the REPL accepts :precision N. Exact poles, incompatible dimensions, and unsupported domains are runtime errors rather than sentinel values.

Constraints and assumptions

Assumption calls attach session-local facts to a variable and return that value. Contradictory sign assumptions are rejected. SCAS deliberately prefers an unsimplified correct expression over a branch-unsafe rewrite, so every conditional identity is gated on an explicit constraint.

SignatureFact recorded
assume_real(x)x is real.
assume_integer(x)x is an integer and therefore real.
assume_nonzero(x)x ≠ 0.
assume_nonnegative(x)x ≥ 0 and real.
assume_positive(x)x > 0, real, nonnegative, and nonzero.
assume_negative(x)x < 0, real, and nonzero.
assume(constraint)A comparison (==, !=, <, <=, >, >=) with a plain variable on one side, or an and combination of them. Equality facts substitute into later expressions; later assumptions that fold to false are rejected as contradictions.
forget_assumptions()Clears every recorded fact.

What each fact unlocks for an unconstrained symbol x (which keeps x/x, sqrt(x^2), exp(ln(x)), and ln(exp(x)) verbatim):

FactIdentities it permits
realln(exp(x)) -> x, sqrt(x^2) -> abs(x)
nonzerox/x -> 1, x % x -> 0, x^a/x^b -> x^(a-b), exp(ln(x)) -> x
nonnegativeabs(x) -> x, sqrt(x^2) -> x
positiveall of the above plus the positive-log/exponent forms
integerparity and divisibility reasoning where relevant

let B = [2, 0; 1, 2];
print(A');          // [[1, 3], [2, 4]]
print(A * B);       // [[4, 4], [10, 8]]
print(A * [5, 11]); // [27, 59]

Documenting variants

Each function below returns the normal result plus structured derivation data used by the document renderer: transpose_steps, trace_steps, det_steps, rank_steps, rref_steps, inverse_steps, matmul_steps, dot_steps, cross_steps, norm_steps, and solve_linear_steps. Their arguments match the corresponding base function. Inside a render marker, function(args) =>; automatically selects the documenting variant.

Domains, branches, and errors

  • Complex elementary results use conventional principal branches. Complex numbers are intentionally unordered.
  • atan2, hypot, ordering, rounding, min, max, and sign require real inputs.
  • Complex gamma, lgamma, erf, and erfc are explicitly unsupported.
  • Matrix dimensions must align, row shapes must be rectangular, and inverse/linear-solve inputs must meet their uniqueness requirements.
  • Resource ceilings produce structured limit error diagnostics.
