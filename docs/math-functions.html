Exact first. Decimal when requested.

SCAS keeps integers, rationals, and symbolic constants exact. Ask for a decimal approximation when you need one, with a precision you control.

Exactness and precision

print(sin(pi / 6));    // 1/2
print(log(8, 2));      // 3
print(gamma(6));       // 120
print(sqrt(2));        // sqrt(2)
print(evalf(sqrt(2))); // decimal at the active precision
print(sqrt(2.0));      // decimal input requests approximation

The active precision defaults to 100 significant digits. Set it with --precision N for a batch run or :precision N in the REPL. SCAS uses guard digits internally and rounds the displayed result to the requested precision.

Complex values and branches

When an elementary result is not real, SCAS returns its principal complex value. Square roots, logarithms, inverse trigonometric and hyperbolic functions, and fractional powers use their principal branches. cbrt keeps the real cube root for real inputs. Exact poles such as tan(pi/2) produce errors.

Complex values support arithmetic, integer powers, equality, and abs; they are unordered. atan2, ordering, rounding, min, and max require real inputs. Complex special functions such as gamma and erf remain outside the current implementation.

Assumptions protect symbolic rewrites

SCAS does not treat an unknown symbol as positive or even real. State what you know before asking for identities that depend on a domain:

print(sqrt(x^2));    // unsimplified
assume_real(x);
print(sqrt(x^2));    // abs(x)
assume_positive(x);
print(sqrt(x^2));    // x
forget_assumptions();

Helpers include assume_real, assume_integer, assume_nonzero, assume_nonnegative, assume_positive, and assume_negative. Use assume(x > 0 and x < 10) for bounds. Contradictory numeric facts are rejected.
